# ORVIBO-CT30W 红外转发+Home Assistant 接入项目需求文档与实现思路
## 一、项目概述
本项目基于 ORVIBO-CT30W 开发板（核心芯片 ESP8266EX），实现“红外信号复杂转发”与“Home Assistant（HA）远程控制”两大核心功能，支持红外映射表灵活配置、网络便捷配网，同时保障红外转发高性能与接口低耦合，适用于多设备红外信号联动场景（如电视多信号开机、家电红外指令统一管理）。

## 二、核心需求
### （一）红外信号转发功能
1. **协议兼容**：支持 NEC、RC5、RC6、Sony、SAMSUNG 等常见红外协议，兼容无标准协议的原始时序信号。
2. **复杂信号支持**：可配置 A 信号触发后，B 信号的序列组合（最多≥5个连续信号）、信号间隔时间（0-1000ms 可配置）、重复次数（1-10次可配置），满足多信号触发场景。
3. **映射规则灵活**：支持“一对多”“多对一”映射，一个 A 信号可对应多组 B 信号（按场景切换），多个 A 信号可映射到同一组 B 信号。
4. **学习与代码输出**：支持手动触发"学习 A/B 信号"，自动解析信号特征并输出（原始时序、协议+数据、十六进制压缩格式）；支持串口打印、HA 接口查询、本地日志存储（最近50条）三种输出方式。
5. **转发性能**：A 信号接收后 B 信号发射延迟≤50ms；连续信号间隔误差≤20ms（使用硬件定时器实现）；支持缓存最近5个未处理信号，不丢失并发接收的短时间多 A 信号。
6. **映射表限制**：最大支持50条映射规则，单条规则最多5个连续B信号，满足常见使用场景。

### （二）Home Assistant 接口功能
1. **通信方式**：优先 MQTT（轻量低延迟），RESTful 接口作为可选扩展功能（第二阶段实现）。
2. **支持操作**：查询所有映射规则、新增/修改/删除映射、触发指定映射转发、获取红外接收日志、上传自定义 B 信号序列。
3. **状态反馈**：HA 调用后返回"成功/失败/执行中"状态，红外转发结果实时推送至 HA；断网时不影响本地红外转发功能。
4. **性能要求**：MQTT 接口响应时间≤300ms（受网络延迟影响），HA 接口请求不阻塞红外接收/发射线程。

### （三）网络配置功能
1. **配网模式**：默认 AP 配网（网页端配置，无需 APP）+ 串口 AT 指令配网（备份）。
2. **参数持久化**：WiFi SSID/密码、MQTT 服务器地址/端口/账号密码等存储在 Flash，重启自动加载。
3. **自动重连**：WiFi 断开后5秒内自动重连（最多10次），失败则重启 AP 配网；MQTT 随 WiFi 重连自动恢复。
4. **状态反馈**：通过板载 LED 指示网络状态（AP 模式慢闪、WiFi 连接中快闪、连接成功常亮、MQTT 离线闪烁），网络状态同步推送至 HA。
5. **资源隔离**：网络配置线程优先级最低，重连过程异步执行，不影响红外核心功能。

### （四）辅助功能与性能约束
1. **容错处理**：自动丢弃无效红外信号（噪声、不支持协议）；发射失败记录日志并推送 HA 告警；配置参数保存前合法性校验。
2. **配置便捷性**：支持 HA 面板、串口 AT 指令配置映射表，无需电脑烧录；映射表支持 JSON 格式导入导出，修改后实时生效无需重启。
3. **状态指示**：板载白色 LED（GPIO15）反馈设备状态（接收信号闪烁、发射信号长亮、异常快闪、网络状态映射）。
4. **资源占用约束**：
   - ESP8266 运行时内存占用≤50%（约40KB，需严格控制缓冲区大小）；
   - CPU 占用转发时≤70%，接口调用不额外增加转发负载；
   - 映射表最大50条规则，日志保留最近50条（循环覆盖）；
   - 接收环形缓冲区限制为4-6KB，避免内存溢出。

## 三、实现思路
### （一）整体架构设计（分层解耦）
采用“核心层+扩展层”架构，通过线程隔离与消息队列解耦，保障红外转发核心性能：
```
硬件适配层 → 红外核心处理层（高优先级）→ 消息队列 → 扩展层（HA 接口层+网络配置层，低优先级）
                ↓
              配置持久化层（Flash）
```

### （二）分阶段实现步骤
#### 阶段0：网络配置开发（1-2天）
1. **AP 配网实现**：设备无有效 WiFi 配置时自动创建热点（SSID：ORVIBO-CT30W，密码：12345678），启动轻量 Web 服务器（ESP8266WebServer 库），提供极简配置界面（WiFi+MQTT 参数输入）。
2. **串口配网实现**：支持 AT 指令（如`AT+WIFI=SSID,PASSWORD`）配置网络参数，串口返回执行结果。
3. **参数存储与重连**：定义`NetworkConfig`结构体，序列化后存储在 Flash SPIFFS 分区；实现 WiFi/MQTT 自动重连逻辑，重连失败切换 AP 配网。
4. **网络状态反馈**：绑定 LED 状态与网络状态，通过 MQTT 推送网络状态至 HA。

#### 阶段1：硬件适配与基础驱动开发（1-2天）
1. **引脚初始化**：
   - 红外接收（GPIO5）：输入模式+外部双边沿中断，绑定中断回调函数；
   - 红外发射（GPIO14）：输出模式，软件模拟 PWM 适配多协议；
   - 辅助引脚：GPIO4（按钮，下拉输入）、GPIO15（LED，输出）。
2. **基础驱动实现**：
   - 接收驱动：中断回调中记录"电平状态+μs级时间戳"，存储到环形缓冲区（4-6KB 大小，根据内存占用动态调整）；
   - 发射驱动：编写`ir_transmit(timing_data)`函数，按时序数组切换 GPIO 电平并使用硬件定时器精准延时；
   - 测试验证：用红外 APP 发送信号，验证接收时序捕捉与发射信号复现功能。

#### 阶段2：核心红外处理功能开发（3-4天）
1. **信号解析模块**：
   - 协议解析：实现常见协议（NEC/RC5等）解析逻辑，提取“协议+数据”；未匹配协议信号用“时序特征哈希值”作为标识；
   - 连续信号识别：通过500ms 超时阈值，合并同一组连续信号。
2. **映射表管理模块**：
   - 数据结构：定义`IR_MapRule`结构体（A 信号标识、B 信号序列、间隔、重复次数等）；
   - 存储与操作：映射表 JSON 格式存储在 SPIFFS，启动时加载到内存数组（最大50条，线性搜索足够快≤5ms）；实现增删改查函数，支持实时更新并立即保存到 Flash。
3. **转发执行模块**：
   - 预编译优化：设备启动时将 B 信号“协议+数据”预编译为时序数组，减少转发耗时；
   - 转发流程：接收线程捕捉 A 信号→解析标识→查询映射表→通过消息队列提交发射任务→发射线程按配置执行序列发射。
4. **学习模式实现**：短按 GPIO4 学习 A 信号，长按学习 B 信号，学习完成后串口打印代码+LED 确认。

#### 阶段3：Home Assistant 接口开发（1-2天）
**优先级**：先实现 MQTT 接口，RESTful 接口作为可选扩展。
1. **MQTT 客户端配置**：基于`PubSubClient`库，连接 HA 的 MQTT 服务器，定义固定主题：
   - 指令主题（HA→设备）：`homeassistant/orvibo-ct30w/command`；
   - 状态主题（设备→HA）：`homeassistant/orvibo-ct30w/state`；
   - 日志主题（设备→HA）：`homeassistant/orvibo-ct30w/log`。
2. **接口功能实现**：
   - 独立 MQTT 线程（低优先级）处理 HA 指令，通过消息队列与红外核心层交互；
   - 定义 JSON 指令格式（如查询映射：`{"action":"query_maps"}`），实现指令解析与响应。
3. **状态同步**：红外转发结果、设备异常状态实时推送至 HA，HA 调用返回明确执行状态。

#### 阶段4：性能优化与功能验证（2-3天）
1. **性能优化**：
   - 线程优先级配置：红外接收（最高）> 红外发射（中）> MQTT（低）> 网络配置（最低）；
   - 缓冲区优化：接收环形缓冲区采用“覆盖机制”，保障最新信号优先处理；
   - 中断控制：发射函数关闭中断时长≤10ms，避免影响接收。
2. **功能验证**：
   - 复杂信号转发测试：配置3个连续 B 信号，验证延迟与间隔误差；
   - 并发与接口测试：同时发送10个 HA 指令+多 A 信号，验证转发不卡顿、接口响应及时；
   - 稳定性测试：24小时连续转发，检查信号丢失、内存泄漏情况。

#### 阶段5：辅助功能完善（0.5-1天）
1. 映射表导入导出：实现`map_import()`/`map_export()`函数，支持串口/HA 接口操作；
2. 日志管理：本地日志保留最近50条（循环覆盖），HA 可查询历史日志；
3. 容错与告警：完善无效信号过滤、发射失败重试、配置错误告警逻辑。

### （三）关键技术与工具
1. **开发环境**：PlatformIO（跨平台、结构化管理、编译优化可控）；
2. **核心库**：
   - 红外处理：IRremoteESP8266（协议解析+发射）；
   - 网络通信：ESP8266WiFi、ESP8266WebServer、PubSubClient（MQTT）；
   - 数据处理：ArduinoJson（JSON 序列化）；
   - 存储：SPIFFS（Flash 文件系统）；
   - 线程管理：FreeRTOS（ESP8266 自带）。
3. **测试工具**：红外接收器、串口助手、Home Assistant（MQTT 联调）。

### （四）难点与解决方案
| 技术难点 | 解决方案 |
|----------|----------|
| 红外信号解析准确率低 | 增加协议校验（如 NEC 地址反码验证），过滤<50μs 噪声脉冲，多次接收取平均值 |
| 连续信号间隔误差大 | 用硬件定时器（ESP8266 Timer1）替代`delay()`，精准控制间隔，误差≤20ms |
| 接口与转发耦合 | 独立线程+消息队列异步交互，HA 请求不直接操作红外硬件 |
| 配置丢失风险 | 映射表与网络配置双分区备份，Flash 写入采用"写时复制"机制 |
| 网络重连占用资源 | 重连线程低优先级，采用"延迟执行+失败退避"策略，减少 CPU 占用 |
| 内存资源紧张 | 严格控制缓冲区大小（接收4-6KB，日志50条），映射表限制50条，使用固定大小数组避免动态分配 |
| 单核性能限制 | 通过线程优先级和消息队列解耦，红外核心功能最高优先级，网络功能最低优先级 |

### （五）资源约束与实现限制
**硬件资源**：
- ESP8266EX：80KB RAM，单核 80MHz，4MB Flash（典型配置）
- 内存分配策略：
  - 接收环形缓冲区：4-6KB（根据实际使用动态调整）
  - 日志存储：50条×平均400字节≈20KB
  - 映射表：50条×平均200字节≈10KB
  - 系统与网络缓冲区：剩余约4-6KB
  - 总计控制在40KB以内（≤50%）

**性能约束**：
- 映射表查询：使用线性搜索（≤50条时足够快，≤5ms）
- 消息队列：固定大小数组（5个信号缓存），避免动态分配
- 线程优先级：接收（最高）> 发射（中）> MQTT（低）> 网络配置（最低）

**功能优先级**：
- **第一阶段（核心功能）**：红外转发、MQTT 接口、基础配网
- **第二阶段（扩展功能）**：Web 配网、日志管理、映射表导入导出
- **第三阶段（可选功能）**：RESTful 接口、高级容错机制
