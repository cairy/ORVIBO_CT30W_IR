# 信号格式说明

本文档详细说明设备使用的红外信号数据结构。

---

## 单个信号（UnifiedSignal）

单个红外信号包含以下字段：

```json
{
  "protocol": 1,           // 协议类型（1=NEC, 2=RC5, 3=RC6, 4=Sony, 5=Samsung, 0=未知）
  "data": "0x00003039",    // 协议数据（32位十六进制字符串）
  "useTiming": false,      // 是否使用时序码（true=时序码，false=协议信号）
  "timingBase64": "",      // 时序码 Base64 字符串（仅当 useTiming=true）
  "timingCount": 0,        // 时序点数量（仅当 useTiming=true）
  "repeatCount": 1         // 重复发送次数（默认 1）
}
```

### 字段说明

- **protocol**：协议类型编号
  - `1` = NEC（最常见）
  - `2` = RC5（飞利浦）
  - `3` = RC6（飞利浦）
  - `4` = Sony
  - `5` = Samsung
  - `0` = 未知协议（使用时序码）

- **data**：协议数据，十六进制字符串格式（如 `"0x00003039"`）

- **useTiming**：信号类型标志
  - `false`：标准协议信号，使用 `protocol` 和 `data` 字段
  - `true`：时序码信号，使用 `timingBase64` 和 `timingCount` 字段

- **timingBase64**：时序码的 Base64 编码字符串（仅时序码信号）

- **timingCount**：时序点数量（仅时序码信号）

- **repeatCount**：信号重复发送次数（默认 1）

### 示例

**NEC 协议信号**：
```json
{
  "protocol": 1,
  "data": "0x00003039",
  "useTiming": false,
  "timingBase64": "",
  "timingCount": 0,
  "repeatCount": 1
}
```

**时序码信号**：
```json
{
  "protocol": 0,
  "data": "0x00000000",
  "useTiming": true,
  "timingBase64": "ABC123XYZ456...",
  "timingCount": 156,
  "repeatCount": 1
}
```

## 信号序列（SignalSequence）

一个红外命令由信号序列表示，单个信号也是序列（`signalCount=1`）。

```json
{
  "signals": [             // 信号数组（最多 5 个）
    {
      "protocol": 1,
      "data": "0x00003039",
      "useTiming": false,
      "timingBase64": "",
      "timingCount": 0,
      "repeatCount": 1
    }
  ],
  "intervals": [0, 30, 70]  // 间隔数组（毫秒）
}
```

### intervals 数组语义

**情况 1：intervals 数量 = signalCount**  
`intervals[0]` 表示第一个信号前的间隔，`intervals[i]` (i>0) 表示 `signals[i-1]` 和 `signals[i]` 之间的间隔。

示例：
```json
{
  "signals": [{...}, {...}],
  "intervals": [50, 30]
}
```
表示：等待 50ms → 发送信号 1 → 等待 30ms → 发送信号 2

**情况 2：intervals 数量 = signalCount - 1**  
`intervals[i]` 表示 `signals[i]` 和 `signals[i+1]` 之间的间隔（标准模式）。

示例：
```json
{
  "signals": [{...}, {...}],
  "intervals": [30]
}
```
表示：发送信号 1 → 等待 30ms → 发送信号 2

### 序列示例

**单个信号（无第一个信号前间隔）**：
```json
{
  "signals": [{...}],
  "intervals": []
}
```

**单个信号（有第一个信号前间隔）**：
```json
{
  "signals": [{...}],
  "intervals": [50]
}
```
表示：等待 50ms → 发送信号

**多个信号（标准模式）**：
```json
{
  "signals": [{...}, {...}],
  "intervals": [30]
}
```
表示：信号 1 → 等待 30ms → 信号 2

**多个信号（有第一个信号前间隔）**：
```json
{
  "signals": [{...}, {...}],
  "intervals": [50, 30]
}
```
表示：等待 50ms → 信号 1 → 等待 30ms → 信号 2

## 字符串序列格式

API 发送信号支持简洁的字符串格式，便于手动输入和调试。

### 格式规则

```
signal1[@interval1];signal2[@interval2];signal3[@interval3]|repeatCount
```

- **`;`** 分隔多个信号
- **`@间隔毫秒数`** 表示与下一个信号的间隔（可选，默认 0）
- **`|repeatCount`** 表示序列级别的重复次数（可选，默认 1）
- **第一个信号前的间隔**：如果第一个信号段以 `@` 开头，例如 `@50;signal1@30;signal2|1`

### 信号格式

**协议格式**：`protocol,data[,repeatCount]`
- 示例：`1,0xFF00FF00` 或 `1,0xFF00FF00,2`

**Base64 格式**：时序码的 Base64 编码字符串
- 示例：`ABC123==`

**数组格式**：时序码数组
- 示例：`[8991,-4546,1000,-500]`

### 示例

**单个信号**：
- `ABC123==|2` - Base64 信号，重复 2 次
- `[8991,-4546]|3` - 数组信号，重复 3 次
- `1,0xFF00FF00,2` - NEC 协议信号，重复 2 次

**两个信号的序列**：
- `ABC123==@30;DEF456==|2`  
  表示：信号 1 → 等待 30ms → 信号 2，整个序列重复 2 次

**三个信号的序列**：
- `[8991,-4546]@50;[1000,-2000]@30;[3000,-4000]|1`  
  表示：信号 1 → 等待 50ms → 信号 2 → 等待 30ms → 信号 3

**协议格式序列**：
- `1,0xFF00FF00@30;2,0x12345678@50;1,0xABCDEF00|2`  
  表示：3 个协议信号，带间隔，序列重复 2 次

**混合格式序列**：
- `ABC123==@30;[8991,-4546]@50;1,0xFF00FF00|1`  
  表示：Base64 信号 → 数组信号 → 协议信号

**第一个信号前间隔**：
- `@50;ABC123==@30;DEF456==|1`  
  表示：等待 50ms → 信号 1 → 等待 30ms → 信号 2

## 支持的协议

| 协议 | 协议 ID | 说明 | 数据格式 |
|------|---------|------|----------|
| **NEC** | 1 | 最常见的红外协议 | 32 位数据（地址+命令） |
| **RC5** | 2 | 飞利浦 RC5 协议，曼彻斯特编码 | 13 位数据（控制位+地址+命令） |
| **RC6** | 3 | 飞利浦 RC6 协议，支持模式位 | 20 位数据 |
| **Sony** | 4 | 索尼协议，支持 12/15/20 位格式 | 12/15/20 位数据（自动识别） |
| **Samsung** | 5 | 三星协议，类似 NEC 但引导码不同 | 32 位数据（地址+命令） |

### 协议解析特性

- 使用 IRremoteESP8266 库进行协议解析，准确率 >99%
- 自动识别协议类型和数据格式
- 支持 NEC 重复码检测
- 未匹配协议自动使用时序特征哈希值作为标识
- 相同按键每次接收都能得到相同的协议数据值

## 重复码处理

### NEC 重复码

NEC 协议支持重复码（`0xFFFFFFFF`），用于长按检测。

- **重复码间隔**：100-120ms（NEC 协议标准约 108ms）
- **发送重复码**：如果信号的 `repeatCount > 1`，发送 1 次完整信号 + (repeatCount-1) 次重复码
- **重复码间隔**：110ms（NEC 协议标准）

示例：
```json
{
  "protocol": 1,
  "data": "0x00003039",
  "useTiming": false,
  "repeatCount": 3
}
```
发送：完整信号 → 等待 110ms → 重复码 → 等待 110ms → 重复码

---

## 注意事项

1. **数据格式统一**：所有信号数据（`data` 字段）统一使用十六进制字符串格式（如 `"0x00003039"`）
2. **单个信号也是序列**：当 `signalCount=1` 时，`intervals` 可以为空 `[]` 或包含一个值 `[delay]`
3. **序列检测逻辑**：间隔 <1000ms 视为同一序列，间隔 >5000ms 视为新序列开始
4. **录制的信号可直接使用**：学习结果、最近接收的信号和规则中的信号可以直接相互拷贝使用
