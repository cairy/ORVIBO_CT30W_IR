学习

多个指令名用逗号分开，中英文逗号都认（也能用顿号「、」或分号）； 最多 8 个。填好后点「启动学习」，再对着设备一个一个按遥控器。

学习结果

每个指令都能单独处理： 发送＝立刻把这条码发出去（顺手验一下学对没有）； 保存到设备＝存进「设备」页，以后在那儿一键发送； 设为 A / 设为 B＝拿去建转发规则——想让别的遥控器触发它，就把它设为 B。

学习结果会保存在设备里（约 1 KB 闪存，不占内存）：重启 / 断电 / 升级 都不会丢，开始下一次学习时才自动覆盖。它只是「还没处理」的暂存 —— 用上面的按钮设为 A/B 或保存到设备之后，才算正式记下。 结果没出来时点「刷新结果」（刚学完那一下设备内存最紧，等几秒通常就读到了）； 不想要了就点「清除结果」。

规则

信号字符串怎么看？

一串信号 = 若干「信号段」用 ; 连起来，末尾可以跟一个重复次数。 每一段本身是下面三种写法之一。

写法长什么样 / 什么意思
协议码 1,0x00003039
逗号前是协议号，逗号后是码值。协议号：1=NEC、2=RC5、3=RC6、4=Sony、5=Samsung； 码值是十六进制，设备输出时固定写 8 位。
时序码 +Eg0NDA…
学习时录下的整段原始波形，是一串 base64 文本。照抄就行，不用看懂。
时序数组 [9000,4500,560,-560]
手写波形时才用。数字单位是微秒：正数=红外灯亮，负数=灭。
符号含义
;分隔两个信号段。
@数字 等这么久再发下一条，单位毫秒。写在整串最前面，表示第一个信号发出去之前先等这么久。
|数字 写在整串最末：整串重复发几次。如 |3 就是连发 3 遍。
,数字 跟在协议码后面：这一条重复发几次。如 1,0x00003039,3。

按这个读一遍 1,0xFD48B7@40;1,0x00FD48B7：先发一次 NEC 码 FD48B7， 等 40 毫秒，再发一次同一个码。0xFD48B7 和 0x00FD48B7 是同一个数， 只是补零位数不同，两种写法都认。

两条输入框的区别：A（触发信号）只能填一条， 填多段会保存失败；B（转发序列）可以填多条，用 ; 隔开。

不想手写就别手写：在「最近」页按下遥控器抓一条，或在「学习」页录下来，直接复制粘贴。

设备

导出与 Home Assistant 怎么用？

导出备份 / 导入备份：本设备的完整配置，导回来一字不差。 导入按设备名合并，不会清空已有设备。

导出给 HA：给 Home Assistant 的 SmartIR 用，一个设备一个文件。 点按钮后在菜单里选格式：

  • 原样 —— 信号串一字不改，任何协议都能导。 HA 侧 controller_data 填本机订阅的四个主题之一： smartir/media_player/<名字>/send （电视用 media_player，空调 climate，风扇 fan，灯 light）。
  • Raw 波形 —— 值写成带符号数组 [9000,-4500,…]（正=发光、负=灭），给 ESPHome 这类自己发波的控制器。 只支持时序码与 NEC 码，其余协议跳过并提示。

文件放进 custom_components/smartir/codes/<平台>/ 并改名成数字 （如 9999.json），HA 配置里写 device_code: 9999。

还没有设备。点右上角「添加设备」新建，或在「最近信号」里对一条信号点「保存到设备」。

点按钮发送信号；长按改名或改信号；点右上角 × 删除按钮。

设置

把本页当文件直接打开时，需要手填设备地址（如 192.168.1.100）； 直接在浏览器里访问设备地址打开本页时，留空即可自动使用当前地址。

网络与 MQTT 配置

配网页里可以搜索周边 WiFi、修改 MQTT，也能一键回退到上次能联网的配置—— 配错了不用接串口。它和本面板共用一套配色，深浅色都跟着系统走。

本页面通过设备 HTTP API 操作红外转发器。信号用的是统一字符串格式（如 1,0x00003039）， 可以从最近信号、学习结果、规则里直接复制粘贴，不用自己拼。 这串字符怎么读，见「规则」页顶部的「信号字符串怎么看？」。手机与设备需在同一局域网。
